# NotebookLM 技術調査報告書：安定稼働に向けた知見集

## 1. 根本原因：ダウンロード失敗のメカニズム
音声生成が「完了」しても直後にダウンロードが失敗（"Could not extract download URL"）する理由は、以下の2段階の不整合にあります。

| フェーズ | 現象 | 詳細 |
| :--- | :--- | :--- |
| **1. 反映ラグ** | 完了 ≠ 準備完了 | ステータスが `COMPLETED` になっても、ダウンロード用 URL がメタデータに書き込まれるまで **5〜30秒のタイムラグ** がある。 |
| **2. 実装の不備** | チェック漏れ | ライブラリの `poll_status` は URL を確認するが、`download_audio` は完了ステータスのみを見て即座にパースを試みるためエラーになる。 |

---

## 2. システム制限とクォータ (Quotas & Limits)
運用上、以下の数値制限を考慮したパイプライン設計が必須です。

| 項目 | 制限値 | 補足 |
| :--- | :--- | :--- |
| **ノートブック総数** | 最大 100 個 | 超過すると新規作成が silent に失敗するかエラーになる。定期的な全削除が必要。 |
| **ポッドキャスト生成** | 1日3回 (無料版) | Audio Overview の生成回数。パイプラインの最大スループットを決定する。 |
| **CLI タイムアウト** | 300秒 (5分) | `--wait` の上限。エラーが出ても Google 側では生成が継続されている。 |
| **ソース処理** | 最大 50 個 / 20MB | 大規模ドキュメントは処理に 120秒以上かかり、タイムアウトの原因になる。 |

---

## 3. 認証と運用リスク (Security & Auth)
非公式 API を利用することに伴う固有のリスクです。

*   **アカウント凍結リスク (Issue #228)**: 短時間の過度なリクエストにより Google アカウントがロックされる可能性がある。開発・自動化専用の「捨てアカウント」の使用を推奨。
*   **認証の有効期間**: `storage_state.json` の寿命は **約1〜2週間**。失効時は再ログインが必要。
*   **クロスドメイン制約**: `googleusercontent.com` へのリダイレクト時に認証が脱落し、一時的に `401 Unauthorized` が発生することがある (Issue #273)。
*   **仮想環境の罠**: venv 等で `login` を実行すると Playwright が Python インタプリタを見失いクラッシュする場合がある (PR #279)。

---

## 4. ライブラリ特有の挙動・バグ (Known Issues)
開発時に考慮すべき実装上の注意点です。

*   **言語設定の強制**: `language set ja` を明示しないと、アカウント設定が英語の場合に音声も英語になる。
*   **ステータスコードの不一致**: 音声生成は `3` で完了だが、リサーチ (Deep Research) は `2` または `6` が完了を意味する。
*   **ID解決の曖昧性**: タイトル指定による操作は前方一致検索がルーズなため、常に UUID 形式のフル ID を使用すべき (PR #163)。
*   **ソースの重複**: インポートのリトライ時に同じソースが複数追加されるバグがある (Issue #241)。
*   **チャットの脆弱性**: JSON ストリームのパースが Google の UI 変更に極めて弱く、突然 `ask` が動かなくなるリスクがある。

---

## 5. 解決策：鉄壁の実装方針 (Best Practices)
これらすべての知見を統合した、安定稼働のためのチェックリストです。

1.  **環境整備**: 定期的に全ノートブックを削除し、クォータを常に空けておく。
2.  **生成開始**: レート制限エラーを検知するため、終了コードだけでなく標準出力のキーワード監視を併用する。
3.  **確実な待機**: 
    *   CLI のタイムアウト設定を十分長くする (例: 5400s)。
    *   `COMPLETED` 検知後、**追加で 30秒間 sleep** させて URL の反映を待つ。
4.  **リトライロジック**: ダウンロードに失敗しても即座に終了せず、指数バックオフを伴う 5回程度のリトライループを実装する。
5.  **認証管理**: `storage_state.json` を headless サーバーに転送して運用可能。
